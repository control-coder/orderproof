# 从空工作目录复现本地演示与证据

适用范围：受控 Windows 本机，已可用 Docker Linux 引擎、Node.js、本项目 conda datalab Python 3.12；只使用公开样例，不使用模型凭据。不同宿主系统依赖 Docker 回环端口、文件 ACL 与 Node 版本，未作跨平台实测。不要把本机密码文件打印到终端。

1. 在仓库根目录执行 `conda activate datalab`，以 `python -c "import sys; print(sys.version)"` 确认 3.12，然后 `python -m pip install --no-build-isolation -e .`。
2. `docker version` 必须有 Server；准备 `python:3.12.12-slim-bookworm`、`postgres:17-alpine`、`redis:7-alpine` 这三个经过核实的小型基础镜像；本地不可访问 Docker Hub 时可从经核实的镜像源导入，不改系统全局源。分析镜像 `docker build -t datalab-executor:py312-v1 -f scripts/executor/Dockerfile .`；本机验收时使用 `--build-arg PYTHON_IMAGE=mirror.gcr.io/library/python:3.12.12-slim-bookworm`，结果执行镜像名称相同，构建来源应另行确认。
3. `npm.cmd ci --prefix frontend --no-audit --no-fund` 和 `npm.cmd run build --prefix frontend`。包安装会联网读取依赖，请事先确认源和许可；不可将 `node_modules`、`dist` 提交。
4. `python -B scripts/local_services.py start` 建本项目专用回环随机端口 PostgreSQL/Redis；配置保存在忽略目录，若已存在会重用而非清空。先 `python -B scripts/check_environment.py` 核对镜像和环境；配置存在不等于数据库可用。再 `python -B scripts/serve.py`，浏览器打开 `http://127.0.0.1:18080`；旧端口 8000 在此机不可绑定。仅本地单用户，不暴露公网。
5. 数据工作台创建项目，上传 `examples/orders.csv`，提交汇总任务，去项目记忆提出并明确确认“只含 paid”口径，在报告详情选择该规则并继续，等待独立核验成功，下载 `结果表.csv`，刷新后确认记录仍在。任务无队列投递时保持待执行，由 dispatcher 从数据库补发；失败不当作成功。
6. 验证：`python -B scripts/test_app.py`（真实数据库、队列、Docker）、`python -B scripts/test_postgres.py`（自建临时专用容器）、设置 `$env:DATALAB_DOCKER_TESTS='1'` 后 `python -B -m unittest discover -s tests/datalab -p test_execution.py -v`（真实 Docker），随后 `Remove-Item Env:DATALAB_DOCKER_TESTS`；`node frontend/tests/browser-flow.mjs` 用本机 Edge；`python -B evals/run_suite.py` 为 20+8+8 固定种子评测，`python -B scripts/verify_scale.py` 为十万行模拟规模测试。默认 unittest 未启用集成时的 skipped 不算通过。
7. Ctrl+C 停止本次 `serve.py` 启动的子进程；`python -B scripts/local_services.py stop` 仅停本项目容器，保留数据库卷和本机配置。运行与评测输出位于忽略的 `artifacts/`；不要删除不确定来源的卷、数据库或备份。若缺少必须的镜像或回环端口被占用，应排查本机环境，不能回退到无隔离宿主执行。

可复现命令由实际成功路径整理；第一步使用已存在的 conda datalab 环境而非另建 venv；镜像源、依赖包可用性及速度会随机器变化。生产自动化部署、公网认证、真实 LLM 权限及跨平台运行不在已验证范围。
