# 固定分析运行与环境恢复

当前无模型固定流程不需要 API Key。所有命令从项目根目录运行，Python 仅使用 conda `datalab` 环境。

## 前置条件

1. `conda activate datalab`，执行 `python -m pip install --no-build-isolation -e .`。
2. Docker Desktop 使用 Linux 容器，`docker version` 能返回服务端版本，而不只是客户端信息。
3. 第一次构建需拉取小型 Python 基础镜像；不下载大模型。构建命令只构建执行镜像，不启动旧参考应用。

```powershell
docker build -t datalab-executor:py312-v1 -f scripts/executor/Dockerfile .
python -B scripts/demo_fixed.py
```

成功后 `artifacts/demo/runs/<run_id>/` 包含计划、执行清单、JSON、CSV 和核验报告；样例使用明确的 `trusted-demo-paid-v1` 口径，只计算 paid，不替真实用户确认未知业务规则。

## 回归与真实隔离测试

```powershell
python -B -m unittest discover -s tests/datalab -v
$env:DATALAB_DOCKER_TESTS = '1'
python -B -m unittest discover -s tests/datalab -p test_execution.py -v
Remove-Item Env:DATALAB_DOCKER_TESTS
```

不开启变量时真实测试明确显示 skipped，不能当作通过。真实测试检查非 root、seccomp、权限、只读输入、断网、越界、符号链接、内存/输出限制、超时取消与清理。2026-09-26 已在本机可用 Docker 上实际执行七项真实隔离用例，结果通过；其他机器仍须单独运行。

## 当前环境与恢复

2026-09-26 本机 Docker 引擎已恢复，专用镜像和真实容器测试实际通过。历史故障与恢复记录保存在 docs/development/2026-09-26-部署复现与失败复盘.md；新机器请依照上述前置条件验证，不将历史问题写成当前阻塞。
