# 业务记忆验证

仅使用 conda datalab，依赖由 `python -m pip install --no-build-isolation -e .` 安装。当前仅新增 PostgreSQL 驱动，不创建第二套 Python 环境或 SQLite 生产替代。

## 离线域规则测试

```powershell
python -B -m unittest discover -s tests/datalab -p 'test_memory*.py' -v
```

默认真实 PostgreSQL 测试显示 skipped；离线通过不代表事务、锁或跨进程持久化通过。

## 真实数据库测试

需要一个专用的 PostgreSQL 测试数据库。通过本机安全配置渠道设置 `DATALAB_TEST_DATABASE_URL`，不要把真实连接凭据粘贴到聊天、日志或仓库中；不得指向包含用户原始业务数据的生产库。

确认测试连接已安全配置后：

```powershell
$env:DATALAB_POSTGRES_TESTS = '1'
python -B -m unittest discover -s tests/datalab -p test_memory_postgres.py -v
Remove-Item Env:DATALAB_POSTGRES_TESTS
```

测试创建初始表，每次使用随机 test- 项目范围，只删除自己创建项目下的记录，不删除数据库或业务表。测试包括跨连接复用、历史版本保留和并发确认只能有一个胜者。没有连接配置时应修复环境，不把测试改成内存实现来假装通过。

2026-09-26 已通过 python -B scripts/test_postgres.py 在独立、随机回环端口的临时容器运行两项真实 PostgreSQL 用例；脚本生成本次独立测试密码，不输出密码，仅清理自建测试容器。已有本地服务见 docs/operations/部署复现与验收.md，不依赖固定 5432 端口。
