# 受限执行设计

## 信任边界

可信宿主 runner 管理 Docker；生成代码只在专用容器中执行，不提供宿主执行降级。容器只读挂载当前执行复制的规范化 CSV、分析代码和收集器，不挂载工作区、原始数据目录、Docker socket 或凭据。不同尝试使用新的 UUID 目录和随机容器名，不共享写入路径。

容器采用非 root 用户、默认 seccomp、丢弃全部 capabilities、禁止权限提升、无网络、只读根文件系统，CPU 1 核、256 MB 内存且无额外 swap、32 进程上限和文件描述符限制。只有 16 MB 的 `/output` tmpfs 用于分析产物，不给通用 `/tmp` 写空间。

镜像不运行时安装依赖。执行前把已存在的镜像标签解析为内容 ID，实际按该 ID 创建容器并记入清单；不自动拉取。宿主 datalab 环境与分析镜像的 Python 补丁版本可能不同，重放须以清单中的镜像 ID 为准。

## 输出与生命周期

代码 stdout/stderr 不直接暴露。容器收集器只读取白名单平面普通文件，拒绝符号链接和硬链接；全部输出经受限 JSON/base64 通道返回，宿主再次检查字段、文件名和解码后大小，不解压归档、不执行输出内容。PNG 最多三张，默认 JSON + CSV，总输出上限 8 MB。日志驱动关闭，通道有额外大小上限。

收集器不是数值正确性的权威：同容器产生的任何字节均不可信。宿主通过独立 SQL 参考复算 JSON，并独立比对下载 CSV；容器正常退出只记 `COMPLETED`，不等于分析 `SUCCEEDED`。

超时、取消、异常均强制移除本次容器。无法确认清理时标 `CLEANUP_PENDING`，不返回成功；运行清单记录容器名供受控排查。Docker 服务不可用时记录失败，不尝试在宿主执行代码。宿主被强制终止等崩溃后的自动孤儿回收尚未实现，需按清单人工核对，不批量清理其他容器。

## 验证边界

2026-09-22 已通过离线控制流程和输入/输出检查。真实容器检查已写入测试，但本机 Docker 引擎无响应，未完成隔离验收。上述描述是实现配置和设计，不是已验证的绝对安全承诺。
