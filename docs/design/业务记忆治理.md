# 业务记忆治理

## 权威存储和范围

生产唯一实现是 `PostgresMemoryRepository`，保存到 PostgreSQL。内存仓库只定义在测试文件中，不导出到生产入口；独立数值参考中的临时 SQLite 不承担业务记忆存储。

范围必须包含 project_id、dataset_family、schema_signature，先过滤范围再进行关键词检索。数据家族描述语义，不从 schema 自动推断；相同字段但不同语义必须重新确认。当前不引入向量库或多套记忆权威。

## 生命周期

- 指标、字段语义和展示偏好先产生 pending，只有明确的用户确认或可信预配置调用 confirm 后才默认复用。
- 历史摘要为 recorded，不能因重复访问自动确认为指标规则。
- 确认必须提供看到的当前 memory_id；已有同名规则时不能用空值覆盖。并发确认或页面旧版本触发 MemoryConflict，必须重新展示冲突。
- 新版本确认后旧版本变为 superseded，旧内容、来源和版本不覆盖；报告应保留 MetricSnapshot，不在重放时重新选“最新”口径。
- 失效标记 invalidated，记录操作人和时间；不删除旧报告依赖的内容，也不自动回退到更早版本。

默认检索只返回 confirmed 且已生效的条目，数值计算只从已确认 metric 建立快照。scope、source_run_id、confirmed_by、effective_from、supersedes_id 和版本均持久化。

## 事务与并发

每个范围使用短事务和事务级咨询锁；同名当前确认版本有数据库部分唯一索引。新版本确认与旧版本 superseded 在同一事务中完成，内容字段不被状态更新覆盖。SQL 使用参数绑定，scope 不是拼接 SQL 标识符。数据库连接、语句和锁等待均有有限超时。

`initialize()` 是新数据库的初始建表入口，不是已有生产数据库的自动升级工具；后续字段变更应提供显式迁移，不可清空数据重建。当前没有在本机真实 PostgreSQL 上验收建表、锁与重启复用。
