# 三角色与状态契约

## 独立上下文和权限

Planner 只接收问题、数据概况及已确认口径快照；Analyst 只接收计划、尝试产物 ID 和必要反馈，只编写 `analyze(data, plan)` 函数，计划常量、CSV 读写、编码与公式注入防护由服务端框架（`execution/analysis_frame.py`）生成，组装后的脚本仍进入同一受限容器与独立核验；Reviewer 接收问题、数据概况、计划、产物 ID 与核验检查名和结论（不含独立参考数值）。角色交接中的计划不带 `checks`，核验项由服务端负责。每次调用深复制显式交接，不共享聊天历史，也不自动发送完整订单。

服务端 `BoundTools` 绑定角色和当前任务的处理器；允许的工具名由固定白名单决定，模型响应不能声明自身身份、启用 bash 或传入任意工具注册表。Planner 无执行权限，Reviewer 不能执行分析代码，Analyst 不能代替固定核验。

角色输出分别为 `plan/confirmation`、`code`、`accepted + feedback`。Planner 不能更换已选数据、指标版本或确认的订单状态。角色运行时通过 `RoleBackend` 注入模型适配器，适配器必须实现有限请求超时和实际 token 用量；目前测试使用确定性替身，不代表真实模型已接通。

## 状态和有界修正

程序计算概况后进入计划。缺少确认口径时返回 WAITING_CONFIRMATION，不循环占用 worker；服务端提供适用范围匹配的确认快照后从计划边界恢复。

默认最多 6 次角色调用、12000 token、120 秒有效运行时间。等待用户确认不计时，但恢复后累计调用、token 和已花费运行时间不归零。底层模型适配器应落实剩余请求时限；外层检查超限响应，不能把检查当成对任意不配合适配器的进程强制终止能力。

代码执行失败最多一次修正；独立核验失败时由程序直接把检查名回传 Analyst，最多一次，不调用 Reviewer。反馈附带错误位置而不含期望值：`independent_reference` 给出不一致的字段路径与类型（如 `comparison.growth` 的 value、`total.order_count` 的 type），`download_table` 给出文件缺失、列顺序错误、列不符、行数不符或具体行列不一致；转发前按固定白名单只保留定位字段。即使 Reviewer 接受，独立核验不通过也不能成功。

Reviewer 只在核验通过后调用，职责限定为判断计划是否读对问题（类型、分组、期间），不审查已确认口径、核验项或数值。驳回交回 Planner 复核一次（VERIFYING → PLANNING），而不是让只能改代码的 Analyst 重写：Planner 维持原计划时采用已通过核验的结果，意见记入时间线；给出不同计划时重新执行、核验并再审一次，再次驳回则以 REVIEW_REJECTED 失败；请求澄清时进入等待确认。审查是咨询性的：Reviewer 或复核 Planner 超时、截断、输出不合契约或预算耗尽时，不让任务失败，而是跳过审查、在时间线记录原因（`review_skipped`），采用已通过独立核验的结果；Reviewer 单独使用较低输出上限（默认 2048）与较短超时（默认 60 秒）。清理待确认、执行超时等不能被标成成功。终态重复投递不再次执行。

## 仍待接入的外层

本模块是领域控制核心，不自称数据库或队列。任务领取锁、阶段持久化、崩溃恢复、Redis/Celery 分发及真实模型适配需由后续轮次接入。终态幂等测试不等于并发队列领取已经完成。确认快照目前由可信调用者传入，后续须只通过业务 Memory 确认接口创建，不接受模型自报 confirmed。
